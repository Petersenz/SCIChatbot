ระบบต้องจัดการบริบทของทุกหมวดข้อมูลในขอบเขต ไม่ใช่จำเฉพาะสาขา/อาชีพแล้วเพิ่มข้อยกเว้นทีละคำถาม ส่วน Intent เป็นการเทียบคำหรือความหมายเพื่อเลือกคำตอบ/วิธีตอบที่เตรียมไว้ ไม่ต้องสร้างความสัมพันธ์ซับซ้อนเพิ่ม ต้องไม่บังคับเลือก Intent ที่ไม่ตรงเพียงเพราะมีแถวอยู่ในตาราง

## วิธีที่ปรับ

1. `conversation_plan.py` เป็นจุดกลาง อ่านรายการและชื่อที่มีอยู่จริง เลือกหมวดข้อมูล ขอบเขตสาขา ตัวรายการ ปี/ชั้นปี/เทอม และฟิลด์ที่ถาม ใช้กับทุก provider
2. เก็บบริบทจากคำถามและตัวตนอ้างอิงของห้องนั้น รองรับถามต่อ เปลี่ยนหัวข้อ กลับเรื่องเดิม และอ้างรายการลำดับที่สอง ไม่ใช้คำตอบ AI เก่าเป็นข้อเท็จจริง ไม่อ่านห้องของคนอื่น ถ้าระบุไม่ได้ให้ถามกลับ
3. ดึงรายการที่ทราบ ID จาก DB โดยตรง และกรองชนิดข้อมูล/ขอบเขตก่อนค้นเวกเตอร์ เมื่อไม่มีเอกสารในขอบเขตไม่สร้าง embedding โดยไม่จำเป็น ไม่ดึงอาชีพนอกความสัมพันธ์มาชดเชย
4. Intent คำตรง/คำสุภาพท้ายประโยคใช้ static_response ทันที; คำใกล้เคียงใช้ embedding เดิมในเครื่องเฉพาะข้อความสั้นที่ยังไม่พบหัวข้อสาระ คะแนนอย่างน้อย0.90 และห่างจาก Intent คู่แข่งอย่างน้อย0.08 คะแนนไม่ใช่ความน่าจะเป็นว่าถูกต้อง
5. Cache เฉพาะเวกเตอร์ตัวอย่าง Intent ไม่เก็บข้อความผู้ใช้ใน cache นี้; เปลี่ยนตัวอย่างแล้ว key เปลี่ยน อ่านคำตอบปัจจุบันใหม่ เมื่อ embedding มีปัญหาให้กลับทางปกติพร้อม log ชนิดข้อผิดพลาด ไม่ทำให้แชทล้ม
6. ไม่เลือก RAG intent เมื่อคะแนนเป็นศูนย์หรือเสมอกัน และไม่หยุดที่คำทักทายเมื่อมีคำถาม เช่น “สวัสดี ค่าเทอมเท่าไหร่” ไม่ใช้ Intent เป็นข้อมูลยืนยันข้อเท็จจริง

| ตาราง | หน้าที่ในเส้นทางตอบ |

Intent comparison23ข้อความ: คำตรง5ข้อความเข้าคำตอบสำเร็จรูป; semantic เพิ่ม5ข้อความ เช่น “ฮัลโหล”, “สวัดดี”, “หวัดดีจ้า”; คำถามสาระและตัวอย่างด้านลบไม่ถูกบังคับเป็นคำทักทายในชุดนี้ “ดีครับ” และ “สวัสดีตอนเช้า” ยังไม่ผ่าน threshold ควรเติมเป็นตัวอย่างใน Intent เดิมผ่านหน้าจัดการหลังยืนยัน มากกว่าลด threshold ทั้งระบบ ยังไม่ได้เปลี่ยน Intent ในฐานจริง

คำตรงใน probe ~5–11ms; semantic หลังโมเดลพร้อม ~37–72ms เฉพาะขั้นเทียบ Intent ไม่รวม API/แสดงผล ครั้งแรกโหลดโมเดล ~4.1s; runtime ปกติมี warmup เดิม จึงไม่อ้าง SLA หรือความเร็วทุกครั้ง ไม่ได้ fine-tune หรือเรียนรู้เองจากชุดทดสอบ

## ข้อจำกัดและงานค้าง

- กลไกกลางยังใช้ชุดหัวข้อ/คำใบ้และความสัมพันธ์ที่ระบบมี ไม่ใช่เข้าใจทุกภาษาหรือทุกคำถาม เมื่อภาษากำกวมยังต้องถามกลับ
- อาชีพใหม่20รายการยังไม่มี curriculum_career; ไม่เดาความสัมพันธ์ให้เอง จึงยังตอบรวมเป็นอาชีพวิทย์คอมไม่ได้
- ผลเงินเดือน15000/ค่าเทอม8000เป็นความตรงกับข้อมูลที่เก็บ ไม่ใช่ตรวจความถูกต้องล่าสุดกับต้นทางใหม่
- ข่าว/ข้อมูลทั่วไปบางหมวดยังใช้ชื่อและเนื้อหาระบุสาขาตาม schema เดิม ความสม่ำเสมอของข้อมูลยังมีผล
- ประวัติห้องยาวและจำนวน catalog ที่ขยายมากยังไม่ได้ load test; ครั้งนี้ทดสอบชุดข้อมูลปัจจุบัน
- ยังไม่ทดสอบ candidate นี้ผ่านหน้าเว็บ Production, authenticated CRUD/upload ทั้งเส้นทาง หรือทุก provider ด้วย API จริง
- ไม่มี migration, package ใหม่, เปลี่ยนโมเดล, แก้ secret, restart service หรือ deploy ในรอบนี้ ต้องทดสอบ candidate รวมและขั้นปล่อยระบบก่อนใช้จริง
